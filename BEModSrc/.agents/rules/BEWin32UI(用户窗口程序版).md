# 白易 Win32 用户窗口程序开发规范

## 1. 窗口项目识别与结构

- **识别标识**：项目根目录必须包含 `窗口` 文件夹及 `app.manifest` 文件。
- **目录规范**：
  - `窗口/`：存放用户定义的窗口类逻辑（`.h` 和 `.cpp`）。
  - `窗口/_/`：存放由 XML 布局设计器根据xml文件自动生成的窗口底层用于初始化构建的源代码。
  - `main.cpp`：程序入口文件，该文件名不作强制要求，但需要遵循入口代码规范。
  - `app.manifest`：确保 DPI 感知和现代控件风格（由 IDE 自动管理）。

> 更多完整的窗口程序工程案例（包括多窗口协作、复杂布局、原生控件测试等），请参考白易安装目录下的示例库：`$BEInstall\BEModExamples\BEWin32UI`，
> **AI在开始编码前必读这其中的黄金标杆**：`$BEInstall\BEModExamples\BEWin32UI\选择夹测试`

## 2. 窗口程序集开发规范
白易 VS 插件为置于 **“程序集”**（虚拟目录）内的源文件提供了强大的自动化支持：

- **自动化头文件生成与单文件逻辑定义**：
  > **【重要规范】** 开发白易的窗口程序时，**AI 绝不应该**按照传统 C++ 那样在头文件中写类声明而在源文件中写定义。**必须把所有的类结构、成员函数和事件处理的定义完整写在窗口程序（.cpp）的窗口类内部**（即全部使用 inline 形式）。
  > **窗口 `.h` 是派生文件**：如果 `.cpp` 中已经存在组件成员、成员函数或事件，而 `.h` 尚未同步出来，**不要把 `.h` 为空或缺成员当成代码问题，也不要手工修 `.h`**，直接调用 MCP `generate_cpp_to_h` 同步即可。
  > **【强制动作】** 每当修改、添加或更新窗口程序 `.cpp` 文件中的类结构或逻辑后，**AI 必须立即主动调用 MCP 接口 `generate_cpp_to_h`**（传入项目当前目录作为 `directory`，并传入该 `.cpp` 文件的绝对路径作为 `cpp_path`），以触发后台根据 AST 解析自动同步生成对应的头文件。严禁自行手动维护或忽略头文件的更新。

- **代码与头文件映射示例**：

  **开发者在 `_启动窗口.cpp` 中编写的源文件：**

  ```cpp
  #include <BEMod.h>     // 用户也可自行 #include "../stdafx.h"
  
  struct __启动窗口 : 窗口
  {
      // 所有的事件和业务逻辑的定义都完整写在窗口类内部
      void 事件_创建完毕() 
      { 
          调试输出("你好啊白易语言"); 
      }
  
      void _按钮1_被单击()
      {
          信息框("按钮被单击");
      }
  
      #pragma region 组件成员
      struct _按钮1 : 按钮 {
          void 事件_被单击() { _启动窗口._按钮1_被单击(); } // 事件转发
      } 按钮1;
      #pragma endregion
  
      void 载入(窗口* 父窗 = 0, bool 模态 = 0);
      void 完毕(bool 模态 = 0);
  } _启动窗口; // 定义全局静态实例
  ```

  **插件根据 `.cpp` 自动同步生成的 `_启动窗口.h` 头文件：**
  ```cpp
  #pragma once
  #include <BEWin32UI/BEWin32UI.h>
  
  struct __启动窗口 : 窗口
  {
      void 事件_创建完毕();
      void _按钮1_被单击();
  
      #pragma region 组件成员
      struct _按钮1 : 按钮 {
          void 事件_被单击();
      } 按钮1;
      #pragma endregion
  
      void 载入(窗口* 父窗 = 0, bool 模态 = 0);
      void 完毕(bool 模态 = 0);
  };
  
  extern __启动窗口 _启动窗口; // 声明全局静态实例供跨窗口包含引用
  ```

- **单文件逻辑实现**：由于头文件是自动衍生的，开发者可专注于在一个源文件中实现所有业务逻辑，无需手动维护声明与实现的同步。
- **定义顺序无关性**：在类结构内部，成员函数的实现可以直接写在声明处，且由于在同一个 struct 中，函数间调用无需关心先后顺序。
- **跨窗口交互**：若“窗口2”需要访问“窗口1”的成员或方法，只需在其源文件中 `#include "窗口1.h"` 即可直接调用全局窗口对象 `窗口1`。
- **组件定义要求**：务必保留 `#pragma region 组件成员` 区块并将静态控件都定义于此，这是标准设定以便于插件识别并与 XML 布局设计器进行双向同步。

## 3. 主程序入口规范 (main.cpp)
- **核心包含**：入口源文件包含 `#include <BEWin32UI/runtime.h>`。
- **环境初始化**：开头必须调用 `全局初始化配置(hInstance, true)` 进行白易窗口环境初始化。
- **主窗口启动**：白易框架内钦定 `_启动窗口` 作为唯一合法主窗口，在主函数中链式调用 `_启动窗口.初显(nCmdShow).载入();`（或分别调用）。
- **消息循环**：以 `return Win32消息循环();` 结束入口函数。

**标准 `main.cpp` 入口代码范本：**
```cpp
#include <BEWin32UI/runtime.h>

int CALLBACK wWinMain(HINSTANCE hInstance, HINSTANCE hPrevInstance,
	LPTSTR lpCmdLine, int nCmdShow)
{
	全局初始化配置(hInstance, true);
	_启动窗口.初显(nCmdShow).载入();

	return Win32消息循环();
}
```

## 4. 窗口类开发规范与初始化流程
### 4.1 文件与窗口主类命名规范
- **文件命名**：窗口源文件名（`.cpp`）必须与定义的窗口**实例名**完全同名（例如：实例名为 `窗口1`，则文件名为 `窗口1.cpp`），`窗口/_/`中存放XML与视图设计版CPP（其文件名上它比窗口/中的`窗口1.cpp`后面多一个"下划线"如： `窗口1_.cpp`）。
- **类名约定**：窗口类名(对于子控件也是如此)与其对应的实例名关系固定为：**类名前缀比实例名多一个下划线**（例如：实例名为 `_启动窗口`，则类名为 `__启动窗口`，注意这个启动窗口本身就自带前缀下划线）；
- **继承关系**：所有窗口类必须继承自 `窗口`，对于子控件XML设计器也只认直接继承的组件类（自定义的不予理睬）
- **载入与初始化逻辑**：
  - **`载入()`**：负责创建窗口本体及初始化所有子组件（在 `窗口/_/` 下由xml设计器在 如`窗口1_.cpp` 内自动生成）。
  - **`完毕()`**：组件初始化后的收尾阶段，默认调用 `窗口::完毕(模态)` 以确保子窗口正确处理模态消息循环，用户也可自定义对后期跟布局相关的补充代码。

### 4.2 XML 设计器布局与添加控件
- **首选流程**：窗口的设计期 UI 优先通过 XML 描述，不要直接手写 `窗口/_/窗口名_.cpp` 中由设计器生成的 `载入()`。
- **控件发现**：如果需要确认当前系统有哪些可用窗口控件，可调用 MCP `get_be_sys_components`；该接口属于 UI 专项工具，不属于白易主向导通用流程。
- **属性元信息**：在编写某种窗口/控件 XML 前，必须调用 MCP `get_ui_control_metadata`，传入该控件所在的系统模块名和控件名，例如 `BEWin32UI + 按钮`。该接口只返回该控件 `dllmeta/控件名.hpp` 中的 `static UI属性元信息 META_控件名[] = { ... }` 属性定义块，AI 应以此作为 XML 可写属性、属性类型、枚举值、可空性等信息来源，不要凭经验猜属性。
- **XML 当前格式**：属性直接写在窗口/控件 XML 节点上，而不是旧式 `<属性 .../>` 子节点。窗口使用 `be_version`、`be_rect`，子控件使用 `be_name`、`be_rect`；其中 `be_rect="左,顶,宽,高"`。例如：
  ```xml
  <?xml version="1.0" encoding="utf-8"?>
  <窗口 be_version="1.0" be_rect="50,50,440,272" 标题="测试窗口">
    <按钮 be_name="按钮1" 标题="按钮" be_rect="168,112,96,32" />
  </窗口>
  ```
- **特殊属性限制**：颜色类型是本质是COLORREF可直接写上十进制整数，当元信息中的属性类型为`UI属性类型::字体`、 `UI属性类型::数据` 或 `UI属性类型::自定数据` 时，AI 不得自行猜测、伪造或手写其序列化数据；必须由用户明确提供。如果这类特殊数据属于设计期/布局初始化且确实需要设置，但用户没有提供可直接写入 XML 的数据，则不要硬写 XML，应在窗口类的 `完毕(bool 模态)` 中用对应 C++ API 手工补充初始化。
- **典型复杂初始化**：例如超级列表框的列项、表项，以及其他需要复杂字节集/自定数据的设计期内容，应优先放到 `this->完毕()` 进入后的用户后处理阶段完成，而不是让 AI 猜 XML 数据格式。
- **翻译步骤**：XML 写完或修改后，必须调用 MCP `xml_to_design_cpp`，传入 XML 文件绝对路径，由 `bebuild.exe -xml=<路径>` 将 XML 同步翻译为 `窗口/_/窗口名_.cpp` 设计器代码。
- **生成区边界**：`载入()` 属于 XML 翻译器管理区；翻译器完成窗口、控件、普通属性和设计期布局后，应进入 `this->完毕(模态)`，用户需要保留的二次布局、动态补充控件、复杂数据初始化等写在 `完毕(bool 模态)` 中，最终再调用 `窗口::完毕(模态)`。

- **无 XML 工具时的兜底**：仅当 MCP 中确实不存在 `xml_to_design_cpp` 或调用错误时，才直接在 `窗口/_/窗口名_.cpp` 的 `载入()` 中手写设计期初始化代码。

- **直接实现步骤（仅兜底场景）**：
  在 `窗口/_/` 中对应的 `_窗口名_.cpp`（如 `_启动窗口_.cpp`）的 `载入()` 函数中直接进行手动编写：
   ```cpp
  #include "../_启动窗口.h"
  
  void __启动窗口::载入(窗口* 父窗, bool 模态)
  {
  	if (窗口句柄)return;
  	窗口::创建({});
  	
  	// 示例：静态控件的创建（需在头文件的“组件成员”区域内先声明控件，如：`按钮 按钮1, 按钮2;`）
  	按钮1.创建({ 10, 50, 100, 30 }, this);
  	按钮1.标题_(L"这是一个静态按钮");
      
  	// 备注：所有组件类的参数（如 按钮::参数）初始化前4个成员都是：{左边,顶边,宽度,高度}
      
  	// 你还可以使用具体参数的版本然后再创建：
  	按钮::参数 cs{10, 100, 100, 30};
  	cs.标题 = L"具体参数版本的按钮";
  	按钮2.创建(cs, this);
  
  	窗口::完毕(模态);
  }
   ```
   > **AI 参考标杆示例**：对于静态控件的定义和窗口代码组织，强烈建议参考现成项目的黄金标杆：`$BEInstall\BEModExamples\BEWin32UI\选择夹测试`
   >
   >  如果需要动态创建，更多复杂风格（事件委托、Lambda 绑定等）的完整代码，请参考：`$BEInstall\BEModExamples\BEWin32UI\几种添加控件的风格`
   >

### 4.3 子夹 XML 规则

```xml
<选择夹 be_name="选择夹1" ...>
  <子夹 标题="第一页">
    <按钮 be_name="按钮1" ... />
  </子夹>
  <子夹 标题="第二页">
    <标签 be_name="标签1" ... />
  </子夹>
</选择夹>
```

- `<子夹>` 是多夹组件的结构节点，不是控件，不写 `be_name`。
- `<子夹>` 直接写在多夹组件内部，XML 顺序就是子夹索引（从 0 开始）；子夹只写 `标题`，页内控件按普通控件 XML 规则书写。
- 当 XML 中存在 `<子夹>` 时，`子夹管理` 自定数据由系统根据结构自动生成，AI 不要手写或伪造。
- 涉及网格布局时，调用 MCP `get_be_grid_xml_rules`。

## 5. UI 逻辑与交互规范
- **中文命名**：优先使用中文属性名（`左边`, `顶边`, `宽度`, `高度`, `标题`, `可视`, `内容`, `禁止`）。
- **坐标体系**：参数中的坐标为虚拟单位，框架自动处理 DPI 缩放。
- **属性读写**：读取使用 `内容`，写入使用 `内容_(val)`方法（Setter 风格带有下划线）。
- **编辑框内容读取**：正常情况下可直接读取 `编辑框.内容`。编辑框在内容变化时会自动同步 `内容` 属性；`编辑框._取内容()` 是绕过该缓存、直接从窗口句柄实时读取文本的特殊接口，主要用于 `_不即时写内容属性_` 已开启、自动同步被禁用的场景。
- **事件挂接**：通过覆写 `事件_创建完毕()` 等虚函数处理业务逻辑。在用户代码中**无需**显式写出 `virtual` 或 `override` 关键字，以保持代码简洁。**AI 提示**：事件挂接可以大胆放心直接定义在窗口类的内部，因为这些事件都是虚函数，它们一定能自动导出到编译单元。

## 6. 编码建议
- **视图逻辑分离**：尽量保持 `窗口/_/` 中的代码仅用于 UI 初始化，业务逻辑应放在 `窗口/` 目录下。
- **命名空间**：内部辅助函数建议放入匿名命名空间。
- **内存管理**：通过 `new` 创建的动态控件在调用 `创建()` 并指定父窗口对象后，识别为非静态地址的动态对象将会被自动加入到父窗口的子组件列表中。因此，其生命周期由**父容器类内部自动管理**，在父窗口销毁时会自动释放，开发者**无需手动调用 `delete`**。
- **API 使用优先级**：在实现功能时应遵循以下查找顺序：
  1. **系统模块优先**：优先查找 `BEWin32Base` 和 `BECore` 库中已有的封装方法（这两系统库对于白易窗口开发是已经自动引入的），而其他系统库AI可根据MCP所列举出的已有系统模块库和其描述作为参考确定是否引入。
  2. **用户模块次之**：查看项目 `BEMod` 所列出的是否存在相关已有用户模块的私有功能实现。
  3. **最后自行实现**：若以上库中均未提供所需功能，才考虑调用原生 Win32 API 进行封装实现。
