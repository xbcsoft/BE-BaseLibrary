# 白易基础库0.6 — 总览导航

> 本项目已拆分为三个独立的系统模块库，按层次从底层到上层依次为：
> **BECore（核心基础）→ BEWin32Base（Win32 基础层）→ BEWin32UI（Win32 UI 层）**

### 系统模块所在安装目录获取 `$BEModG`
> **获取方式**：读取注册表 `HKEY_CURRENT_USER\Software\xbcsoft\BE\InstallPath` 得到白易装目录`$BEInstall`，拼接 `/BEModG` 子目录，即`$BEModG`=`$BEInstall+"/BEModG"`。
> **用途**：在跨工程引用或环境配置中，指向白易模块声明的全局根目录，如#include <BECore/BEcore.h>即为指向$BEModG+"/BECore/BEcore.h"。

### 模块内目录规范 

> **适用位置**：｛`$BEModG` 或 用户项目所在`BEMod ` 文件夹｝+"/"+$模块名目录

- **自然语言隔离**：

  白易语言从设计上不排斥英文（更推崇中西结合），既然有“中文核心”、“中文基础扩展”等业务操作入口，自然也为“英文版”保留了位置。未来可以随时单开英文扩展的文件夹单独实现（或是通过一层薄薄的翻译进行重定向包装），这保证了底层核心对象绝对不受任何特定自然语言生态的死板绑定。

  - 英文模块直接采用英文目录名/文件名；中文目录名也**无须包含"中文"**二字。
  - 中英文对应的模块目录**建议保持同级**（例：中文 `核心扩展` 对应英文 `CoreExt`都在同一目录内）。
  - 翻译要求**"直译"**，确保项目内无歧义冲突。

- **平台隔离标识**：

  不打算设计为跨平台通用的模块，需在目录名中显式标明目标平台（如 `Win32`、`Linux`），或通过入口头文件 `@platform` 字段标注指定平台可直接在模块根目录中(无需标明)也可存放（如Win32）相关操作的头文件/源文件。

### 模块相关示例 `BEModExamples文件夹`

> **位置**：安装目录`$BEInstall`下的 `/BEModExamples` 子目录。
> **范例**：按模块名划分（如 `BECore/`、`BEWin32Base/` 等），提供各模块对应的功能使用工程范例。

------

### 💡查阅与开发建议

- **首选查阅声明**：在使用 AI 辅助或手动编码时，请优先在系统模块`$BEModG`路径下的 **头文件** 中查看 API 声明与详细注释。
- **参考范例工程**：若 API 语义不明，可前往 `$BEInstall/BEModExamples/` 目录翻阅对应的使用范例。
- **翻阅模块源码**：当头文件与范例仍无法解决技术细节问题时，可查阅 `$BEInstall/BEModSrc/` 下对应的模块源代码。
- **数据类型偏好**：优先使用白易提供的二级基础数据类型（如 `Bytes`、`StrA/W`、`Arraybe`、`Hashbe` 等），尽量避免直接使用 C++ 标准库类型。

## 1. BECore — 核心基础库

> **定位**：零依赖、跨平台（anysys x86|x64）的相关基础实现，是整个生态的基石。  
> **入口头文件**：`$BEModG/BECore/BECore.h`  
> **skill文档**：[BECore(精简版).md](BECore(精简版).md)（**！AI优先查看！**）、[BECore(完整版).md](BECore(完整版).md)

### 💡 核心设计哲学
BECore 并非简单的工具库，它是白易生态的**原语定义层**：
1. **语义与实现的解耦**：底层由英文 C++ 原语支撑，提供基本二级数据类型，上层通过 `中文核心.h` 实现语义映射，确保逻辑严谨与开发亲和。
2. **内存模型基础**：字符串体系（`StrA`/`StrW`）底层由 `Bytes` 高性能内存管理驱动；而 `Arraybe` 等容器则有各自其独立的策略。
3. **字符集编码**：确立了“A版（StrA）始终视作UTF-8”的准则，通过编译器强制指令与运行时环境初始化，彻底抹平了平台间窄字符串的编码歧义与输出差异，避免了为后续模块及 AI 辅助开发的心智负担。

---

### 英文核心底层

| 文件 | 职责 |
|------|------|
| `bebase.hpp` | C基础类型别名、C++轻量元编程组件 Traits（无std::类与零 STL 依赖的万物基石） |
| `BytesStr.hpp` | `Bytes` / `StrA` / `StrW` / `StrU8` / `StrPlat` 字符串体系，内存布局与编码转换 |
| `Arraybe.hpp` | 泛型动态数组 `Array<T>` |
| `HashTbe.hpp` | 哈希表 `HashT<K,V>` |
| `behelper.hpp` | 全局工具函数、`AutoStr` 等 |
| `beout.hpp` | `be::print` 输出体系 |

### 中文核心映射层

**`中文核心.h`**：对英文核心 API 的中文别名映射，提供 `字节集`、`文本型`、`数组`、`哈希表`、`到文本`、`打印输出` 等关键字。



### 中文核心扩展（`中文核心扩展/` 目录）

| 文件 | 职责 |
|------|------|
| `文本操作.h/.cpp` | 查找 / 替换 / 截取等高级文本指令 |
| `字节集操作.h/.cpp` | 字节集的高级操作 |
| `数组操作.h/.cpp` | 排序、筛选、去重等算法增强 |

## 4. BEVC++ 项目命令行编译

- **白易构建器 (`bebuild.exe`)**（在全局 PATH 环境变量中）

  - **输入目录**：直接通过当前目录打开，从当前路径或其上级目录定位 `.sln`，与当前已打开的 VS-IDE 对接，以解决方案视角编译指定项目（未指定 `-proj` 时使用 IDE 当前启动项目）。
  - **命令参数** (`bebuild --help`):
    - `-proj=项目名`：可空，默认为当前启动项目。
    - `-out=输出文件名`：可空，默认为 `"out\$(TargetName)"`
  - **注意生成目录**：`out` 目录始终是 **项目名所在目录** 的子目录，等同于 `"工程目录\out\$(TargetName)"`，与 `.sln` 所在位置无关。
